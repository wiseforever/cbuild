# 编译器与构建类型配置

状态：已完成。

## 输出目录

- `output_dir_use_subdir` 默认 `true`，在输出目录下追加构建类型。
- `subdir_use_compiler` 默认 `false`；两项均开启时使用 `<编译器>-<构建类型>`。
- 关闭子目录时直接使用输出目录，忽略编译器开关，也不探测编译器版本。
- 未开启编译器隔离时，切换编译器需清理缓存或指定独立输出目录。

## 编译器入口

- `[compiler] compiler` 统一配对 GCC/G++ 或 Clang/Clang++，支持普通名称、版本后缀、交叉前缀、`.exe` 后缀和路径。
- 配套驱动优先从同目录查找，其次按同名规则查找 PATH。
- 未配置或留空时使用环境默认；MSVC 通过独立配置及环境脚本管理。
- 编译器目录前缀由配对的 C++ 驱动识别。GCC 优先通过 `-dumpfullversion -dumpversion` 获取版本，失败时使用版本横幅。
- 版本查询复用 CMake 子进程的临时环境，构建类型切换前完成环境准备。
- 开启编译器前缀但无法查询编译器时，子目录仅包含构建类型。

## 构建类型写回

- Bash 配置写回支持 mawk 1.3.3、CRLF、段标题周围空白及大小写。
- 已有键直接更新；缺少键时插入已有段；缺少段时创建 `[build]`。
- 文件使用 UTF-8 无 BOM、LF。Bash 保留其他配置和注释；Python 保存时统一格式，不保留注释。
- 配置使用唯一的 `[build]` 段；Python 的段名区分大小写。
