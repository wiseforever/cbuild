# 构建类型配置写入兼容性

## 目标与定位

- 排查 Ubuntu 18 上 `cb.sh -t` 看似无效的问题。
- 已复现：`ini_get` 能读取 CRLF 换行及带空白的配置段标题，但 `save_build_type` 只识别严格的 `[build]` 行。写入时追加重复段，下一次运行仍读取原先的 `build_type`。
- 此问题由配置格式触发，并非 Ubuntu 18 独有；是否对应用户现场仍需结合实际配置或输出确认。

## 实施步骤

1. 对齐写入与读取时的配置段识别规则，支持 CRLF、标题前后及名称两侧的空白、大小写。
2. 缺少 `build_type` 时插入已有的 `[build]` 段；仅在缺少该段时新建，避免重复段。
3. 执行命令级回归验证，覆盖持久化、连续切换、显式类型与本地/全局配置选择；按用户要求不保留测试文件。

## 验收标准

- 连续运行两次 `-t`，实际配置按 Release → Debug → Release 切换。
- `-t Debug` 后再次指定 Debug 能识别为已设置。
- 不新增重复 `[build]` 段，不修改未加载的配置文件。
- 保存结果为 UTF-8、LF；保留其他配置及注释。

## 风险与边界

- 写入时将 CRLF 统一转换为 LF，与仓库文件规范一致。
- 不自动合并历史重复段；该修复会更新读取器实际采用的第一个匹配项。
- 不改变 CMake 构建类型选择或 VS Code 调试路径解析逻辑。
