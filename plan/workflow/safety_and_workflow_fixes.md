# 清理安全与构建工作流

状态：已完成。

## 当前规则

- 清理前解析真实路径，拒绝删除源码目录及其祖先目录，包括符号链接别名；允许删除正常构建目录。
- 安装器暂存必需文件，准备成功后才替换目标并清理另一脚本变体；退出时清理暂存目录。可选卸载包装下载失败时保留当前副本。
- Ninja 路径解析和程序列表同时支持 C/C++ 链接规则及冒号后的空白。
- 构建成功以 CMake 退出状态为准。库和自定义 target 不要求生成可执行文件，程序日志及 VS Code 启动路径更新为可选步骤；运行操作严格检查程序。
- 构建目录缓存记录对应的构建类型，类型变化时重新计算；`-t` 持久修改配置，动作参数临时覆盖类型。
- 插件和安装器先查 PATH，再查默认 `~/.cbuild` 或配置的备用目录；每级 Bash 优先。Windows 使用 `where $PATH:<文件名>` 限定搜索范围。
- 全局安装默认 Bash；插件内置源显式选择全局 Bash/Python，项目模板和配置使用独立入口。
- 内置安装以配置目录为 `--prefix`，不自动把 PATH 脚本所在目录推断为更新目标。

## 并发安装限制

- 同一安装目录不支持并发安装或更新，尤其 Bash/Python 变体可能互相删除；不同目录可以独立操作。
- 应等待前一次安装或更新结束后再启动下一次。
- 若脚本入口缺失，等待所有安装进程退出，再向原目录单独安装所需变体。
